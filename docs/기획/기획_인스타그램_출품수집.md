# 인스타그램 출품 수집 · 관리자 검수 · 좋아요 동기화

작성 2026-09-10. 아직 구현하지 않은 기획 기록이다. 아래 API 제약은 Meta·Vercel
공식 문서에서 확인한 값이며, 링크를 함께 남겼다.

관련 코드: `web/src/data/contest.ts`, `web/src/lib/contestRanking.ts`,
`web/src/components/ContestGallery.tsx`

---

## 1. 전체 흐름

```
참가자: 피드 게시물 캡션에 @makji 멘션 (+ #막지_절기레시피)
   │
   ├─ 1차 확인: 인스타그램 앱 알림  ← 개발 불필요
   │
   ▼  Meta가 mentions 웹훅으로 media_id를 밀어준다
POST /api/instagram/webhook          (미구현)
   │  X-Hub-Signature-256 검증 → media_id 저장
   ▼
GET /{ig-user-id}?fields=mentioned_media.media_id({media-id}){username,caption,like_count,media_url,timestamp}
   │
   ▼
저장소에 status='pending' 으로 적재    (저장소 미정)
   │
   ▼  2차 검수
관리자 페이지 /admin/entries          (미구현)
   │  ✓ → approved   ✗ → rejected
   ▼
"취향이 담긴 한 상" 노출              ← 구현 완료
   │  카테고리(제품)별 좋아요 1~3위, 왼쪽이 1위
   ▼
매일 1회 좋아요 재동기화              (미구현)
```

## 2. 수집은 웹훅이어야 한다 — 폴링 불가

### 해시태그 검색은 못 쓴다

`/{ig-hashtag-id}/recent_media`의 문서화된 제약:

- **작성자(`username`)를 요청할 수 없다** → 참가자를 표기할 수 없다
- **조회 시점 기준 24시간 안의 게시물만** 반환 → 관리자가 하루 지나 검수하면 사라진다
- 7일에 고유 해시태그 30개, 페이지당 최대 50건

→ 해시태그는 홍보·안내용으로만 쓰고, 수집의 근거로 삼지 않는다.

### 캡션 @멘션은 목록 조회 엔드포인트가 없다

- `mentions` 웹훅이 캡션·댓글 @멘션을 **실시간으로 밀어준다**. 이때 payload의
  `media_id`(댓글이면 `comment_id`도)를 받는다.
- 그 id로 `mentioned_media` 에지를 물어 내용을 받는다.
- **"내 멘션 목록 다 줘"라는 API는 없다.** 웹훅이 올 때 저장하지 않으면 그 멘션은
  되찾을 수 없다 → **관리자 수동 등록(게시물 URL 붙여넣기) 경로가 필수다.**

### `/tags`는 @멘션이 아니다

`/{ig-user-id}/tags`는 캡션 멘션이 아니라 **사진에 태그된** 게시물이다. 이쪽은
목록 폴링이 되지만 참가자가 사진 태그를 걸어야 한다. 두 경로를 혼동하지 말 것.

## 3. `mentioned_media`에서 받을 수 있는 값

| 필드 | 가능 | 비고 |
| --- | --- | --- |
| `username` | ✓ | 참가자 표기 |
| `like_count` | ✓ | 순위 기준. **작성자가 좋아요 수를 숨기면 값이 오지 않는다** |
| `caption` | ✓ | @ 기호는 제외되어 온다 |
| `media_url` | ✓ | 저작권 신고된 게시물에서는 누락 |
| `timestamp` | ✓ | |
| `permalink` | **✗ 미확인** | 지원 필드 목록에 없다. 아래 참조 |

### ⚠️ `permalink` — 앱 만든 뒤 가장 먼저 확인할 것

"게시글 링크를 가져온다"가 기획의 핵심인데 `mentioned_media` 지원 필드 목록에
`permalink`가 없다. 실제 응답에 오는지 확인이 필요하고, **안 오면 관리자가 URL을
직접 붙여 넣는 경로가 필수가 된다.**

## 4. 참여 조건 / 운영 제약

- **피드 게시물만.** 스토리 멘션은 지원하지 않는다.
- **공개 계정만.** 비공개 계정이 만든 게시물은 웹훅이 오지 않는다.
- **댓글 멘션도 같은 웹훅으로 온다.** 콘테스트와 무관한 멘션·스팸이 섞이므로
  관리자 검수가 반드시 필요하다.
- **인스타그램 프로페셔널(비즈니스/크리에이터) 계정 + 페이스북 페이지 연결** 필요.
- **앱 심사(App Review)** 통과 전에는 본인 계정 데이터만 조회된다.
  → **일정상 가장 큰 리스크.** 심사 전까지는 관리자 수동 등록으로 콘테스트를 돌린다.
- 비용은 무료. 팀당 외부 데이터 예산 $50 제약과 무관하다.

## 5. 좋아요 매일 동기화

Vercel Cron. 확인한 플랜 제약:

| 플랜 | 최소 간격 | 시각 정확도 |
| --- | --- | --- |
| **Hobby (무료)** | **하루 1회** | 시간 단위 (±59분) |
| Pro | 1분 | 분 단위 |

무료 플랜에서 `0 * * * *`(매시) 같은 표현식은 **배포가 실패한다.** 하루 1회는 통과.
"하루마다"가 기획 요구사항이므로 무료 플랜으로 충분하다.

```json
// vercel.json
{ "crons": [{ "path": "/api/contest/sync-likes", "schedule": "0 4 * * *" }] }
```

- **±59분 오차가 있으므로 화면의 "기준 시각"은 예정 시각이 아니라 실제로 가져온
  시각이어야 한다.** `ContestEntry.instagram.likeCountAt`이 그 값이다.
- 동기화 대상은 `approved` 출품. 값이 달라졌을 때만 갱신한다.
- 순위는 `rankByCategory`가 좋아요를 그대로 읽으므로 자동 재정렬된다.

### 처리해야 할 예외

| 상황 | 처리 방침 |
| --- | --- |
| 게시물 삭제 / 계정 비공개 전환 | 마지막 좋아요 수는 보존하되 **순위에서 내리고** 관리자 페이지에 "확인 필요"로 띄운다. 깨진 링크를 노출하지 않는다 |
| 작성자가 좋아요 수 숨김 | API가 값을 주지 않는다 → `likeCount: null`, 카드에 "좋아요 비공개", 순위 맨 뒤 |

### ⚠️ 마감 시점 동기화

하루 1회면 **마감 직전 24시간의 좋아요가 순위에 잡히지 않는다.** 우승을 가리는
값이므로 관리자 페이지에 **"지금 동기화" 버튼**을 두고 마감 때 눌러 확정한다.

## 6. 코드에 이미 반영된 것

- `ContestEntry.status: 'pending' | 'approved' | 'rejected'` —
  `rankByCategory`가 `approved`만 순위에 넣는다. 관리자 ✓/✗가 이 값을 바꾸면 된다.
- `ContestEntry.instagram: InstagramPost` — `mediaId`, `permalink`, `username`,
  `likeCount: number | null`, `likeCountAt`. 좋아요·작성자를 게시물에서 받는 구조.
- 좋아요는 **누를 수 없는 표시**다. 사이트 투표 버튼은 제거했다.
- `productNo`로 카테고리를 잡는다. 출품이 0건인 카테고리는 줄 자체가 생기지 않는다.

## 7. 미결정 / 다음 단계

**저장소 미정.** `contest.ts`가 정적 상수라 크론도 관리자 ✓/✗도 값을 쓸 수 없다
(Vercel 런타임 파일시스템은 읽기 전용, `/tmp`는 호출마다 소멸). 아래 세 가지가
전부 저장소 결정에 막혀 있다.

1. 관리자 페이지 `/admin/entries` — `pending` 목록 + ✓/✗ + URL 수동 등록
2. 웹훅 라우트 `/api/instagram/webhook` — `hub.challenge` 검증 + 서명 검증
3. 좋아요 동기화 `/api/contest/sync-likes` + `vercel.json` 크론

후보: Neon Postgres(Vercel 마켓플레이스), Supabase Postgres(콘솔 테이블 편집기를
임시 관리자 UI로 쓸 수 있음), Upstash Redis.
