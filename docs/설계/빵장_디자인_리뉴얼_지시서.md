# 빵장 디자인 리뉴얼 지시서

> 대상: 막지 빵장 웹 서비스  
> 목표: 전통 식품 브랜드의 정체성과 실시간 시장 서비스의 명료함을 한 화면 안에서 결합한다.  
> 핵심 문장: **국장이 끝나면, 빵장이 열립니다.**

## 1. 리뉴얼 방향

빵장은 일반적인 베이커리 쇼핑몰처럼 보이면 안 된다. 사용자가 첫 화면을 보자마자 아래 세 가지를 순서대로 이해해야 한다.

1. 오늘 주식시장의 움직임이 빵 가격에 영향을 준다.
2. 오늘 할인되는 빵과 가격이 정해진다.
3. 관심 있는 빵을 담고 실제 구매로 이어갈 수 있다.

전체 콘셉트는 **현대적인 장터 시세판**이다. 전통 요소는 한지 질감, 명조 제목, 도장색처럼 제한적으로 사용하고, 정보 영역은 현대적인 고딕체와 정돈된 숫자로 표현한다.

피해야 할 방향:

- 전통 장식이 너무 많아 민속촌·기념품점처럼 보이는 디자인
- 모든 영역을 둥근 카드로 감싸는 전형적인 금융 앱 디자인
- 주가 정보가 제품보다 더 강해 증권 서비스로 오해되는 디자인
- 작은 글자, 과도한 애니메이션, 한 화면에 반복되는 설명

## 2. 디자인 원칙

### 2.1 결과를 먼저 보여준다

사용자가 가장 먼저 봐야 하는 정보는 오늘의 할인 결과다. KOSPI 수치는 결과를 설명하는 근거로 사용한다.

정보 우선순위:

1. 오늘 할인율 또는 개장 상태
2. 오늘의 할인 빵
3. KOSPI 등락과 할인율 산정 근거
4. 관심빵과 구매 행동
5. 상세 규칙 및 부가 정보

### 2.2 전통과 금융의 역할을 분리한다

- 브랜드 문장과 섹션 제목: 명조 계열
- 숫자, 가격, 시간, 상태: 고딕 또는 모노스페이스
- 도장색: 브랜드 강조와 핵심 CTA에만 사용
- 초록/파랑/빨강: 상태 및 등락 의미에만 사용

### 2.3 한 화면에는 하나의 주인공만 둔다

- 상단: 오늘의 시장 결과
- TODAY: 상품과 가격
- MY: 사용자의 관심빵
- 상세 정보: 펼쳤을 때만 노출

같은 크기의 카드가 연속되는 구조는 피하고, 섹션마다 크기와 여백으로 명확한 위계를 만든다.

## 3. 전체 화면 구조

### 3.1 헤더

- 높이: 데스크톱 72px, 모바일 64px 내외
- 왼쪽: 막지 워드마크 + 작은 빵장 낙관
- 가운데 메뉴는 현재 필요한 항목만 유지
- 오른쪽: `막지 공식몰 ↗`
- 스크롤 시 상단에 고정하되, 배경은 미색 반투명 처리
- 공식몰 링크는 얇은 캡슐형 테두리 버튼으로 표현

### 3.2 인트로

기존 한옥 문 열림 연출은 브랜드 첫인상으로 유지한다. 다만 아래 기준을 지킨다.

- 하루 최초 방문에만 자동 재생
- 총 길이는 3초 안팎
- `건너뛰기`는 항상 잘 보이게 제공
- 모션 감소 설정에서는 즉시 본문 노출
- 인트로 안에 너무 많은 수치를 넣지 말고 상태, 등락률, 개장 시각만 표시

### 3.3 메인 히어로

데스크톱에서는 전체 콘텐츠 폭을 사용하는 큰 시세 보드로 구성한다.

- 상단 라벨: `MAKJI / BREAD EXCHANGE`
- 메인 카피: `국장이 끝나면, 빵장이 열립니다.`
- 진한 먹초록 바탕 위에 미색 텍스트
- 오른쪽 배경에 매우 흐린 대형 한자 `場` 또는 `장`
- 주요 숫자는 크게, 설명은 짧게
- KOSPI 차트는 장식이 아니라 할인 결과의 근거로 보이게 배치
- 차트 아래에 오늘의 결론을 한 문장으로 명시

권장 결론 예시:

- 장중: `지금 마감한다면 오늘 빵은 20% 할인`
- 마감 후: `오늘 빵장은 20% 할인으로 확정됐어요`
- 개장 전: `오늘 20:00, 20% 할인으로 열려요`
- 종료 후: `오늘 빵장은 마감됐어요`

### 3.4 TODAY — 오늘의 할인 빵

- 데스크톱: 3열 상품 그리드
- 모바일: 2열 상품 그리드
- 사진 비중을 가장 크게 두고 상품명, 할인가, 정가, 남은 수량 순으로 표시
- 카드 외곽을 반복해서 두르지 말고 사진과 타이포그래피로 구분
- 사진 모서리는 2~4px 정도로 절제
- 관심 버튼은 사진 우측 상단에 배치
- 인기순/관심순은 텍스트 탭으로 단순화
- 할인율은 섹션에서 한 번 설명했다면 카드마다 반복하지 않는다
- 가격은 할인가를 크게, 정가는 작고 흐린 취소선으로 표시

상품 선택 시 바텀시트에서 다음 내용을 보여준다.

- 상품 사진과 이름
- 오늘 가격과 정가
- 왜 이 가격이 됐는지 한 줄 설명
- 남은 수량
- 관심 수량 조절
- 구매 CTA

### 3.5 MY — 관심빵

데스크톱에서는 TODAY 오른쪽의 보조 패널, 모바일에서는 TODAY 아래 섹션으로 배치한다.

- 접힌 상태에서는 `관심빵`, `구매 내역`, `가격 규칙` 세 항목만 보여준다.
- 사용자가 관심빵을 담으면 해당 항목이 가장 먼저 강조된다.
- 도넛 차트는 관심빵이 있을 때만 사용한다.
- 데이터가 없는 상태에서는 차트를 빈 채로 보여주지 않는다.
- 빈 상태 문구는 행동을 직접 안내한다.

빈 상태 예시:

> 오늘 사고 싶은 빵의 하트를 눌러보세요.  
> 관심빵만 모아 할인 여부를 바로 알려드릴게요.

### 3.6 푸터

- 짙은 먹초록 배경
- 브랜드 문장, 공식몰 링크, 저작권 정보만 유지
- 서비스 본문보다 강하게 보이지 않도록 높이를 줄인다.

## 4. 비주얼 시스템

### 4.1 컬러

| 역할 | 권장 색상 | 사용처 |
|---|---:|---|
| 배경 미색 | `#F5F1E7` | 전체 배경 |
| 종이색 | `#FFFCF4` | 상품·정보 영역 |
| 먹초록 | `#1E3329` | 히어로, 푸터, 기본 텍스트 |
| 도장색 | `#A44232` | 브랜드 강조, 핵심 CTA |
| 쑥색 | `#6F8069` | 보조 상태, 그래프 |
| 상승색 | `#B04438` | KOSPI 상승 |
| 하락색 | `#315F87` | KOSPI 하락 |
| 보조 텍스트 | `#77796F` | 설명과 메타 정보 |
| 구분선 | `#D8D3C5` | 얇은 선 |

컬러 사용 규칙:

- 한 화면에서 강한 강조색은 한 종류만 주도하게 한다.
- 도장색은 브랜드와 CTA에만 사용한다.
- 상승/하락 색은 금융 의미가 있는 데이터에만 사용한다.
- 배경 대비는 WCAG AA 수준을 확보한다.

### 4.2 타이포그래피

- 브랜드 제목: `Noto Serif KR`, 600
- 본문과 UI: `Geist` 또는 시스템 고딕
- 숫자와 시간: `Geist Mono`
- 본문 최소 크기: 14px
- 보조 정보 최소 크기: 12px
- 모바일 터치 UI 안의 텍스트는 13px 이상
- 한국어 제목은 `word-break: keep-all` 기준으로 줄바꿈

권장 크기:

| 요소 | 데스크톱 | 모바일 |
|---|---:|---:|
| 메인 카피 | 56~72px | 34~40px |
| 핵심 지수 | 48~56px | 40~48px |
| 섹션 제목 | 24~28px | 21~24px |
| 상품 가격 | 18~22px | 16~19px |
| 본문 | 14~16px | 14px |

### 4.3 간격과 형태

- 기본 간격 단위: 4px
- 콘텐츠 최대 폭: 1180px
- 데스크톱 좌우 여백: 최소 24px
- 모바일 좌우 여백: 16px
- 큰 섹션 간격: 64~96px
- 카드 내부 여백: 20~28px
- 정보 카드 반경: 2~6px
- 버튼 및 바텀시트 반경: 4~8px
- 캡슐형 UI는 상태 태그와 작은 필터에만 사용

## 5. 인터랙션 원칙

- 최초 진입: 인트로 이후 차트 → 결과 → 상품 순서로 등장
- 등장 애니메이션: 300~550ms, 이동 거리 8~18px
- 상품 호버: 최대 4px 상승 또는 사진 1.03배 확대
- 가격 롤링은 최초 노출 또는 실제 데이터 변경 시만 실행
- 실시간 상태 점은 장중에만 움직인다.
- 반복되는 무한 애니메이션은 시세 점과 티커 정도로 제한한다.
- 모든 애니메이션은 `prefers-reduced-motion` 대응
- 정렬 변경 시 카드가 깜빡이거나 등장 애니메이션이 재실행되지 않게 한다.

## 6. 반응형 기준

### 데스크톱: 901px 이상

- 메인 폭 최대 1180px
- 히어로는 전체 폭
- 본문은 TODAY 2 : MY 1 비율의 2열 구조
- MY 패널은 스크롤 중 상단 고정 가능

### 태블릿: 601~900px

- 전체 1열 구조
- MY의 세 항목은 3열 요약 카드로 배치 가능
- 상품은 3열을 유지하되 텍스트가 잘리면 2열로 전환

### 모바일: 600px 이하

- 모든 콘텐츠 1열
- 상품 그리드만 2열
- 메인 카피 2~3줄 이내
- 차트 높이 180~210px
- 구매 CTA 높이 최소 52px
- 모든 터치 영역 최소 44×44px
- 바텀시트는 화면 하단에 고정하고 최대 높이 92vh

## 7. 문구 가이드

톤은 짧고 분명하게 쓴다. 금융 용어를 그대로 노출하기보다 빵장 행동으로 번역한다.

권장:

- `오늘 빵장은 20% 할인으로 열려요.`
- `국장이 많이 움직여 할인 폭이 커졌어요.`
- `관심빵 2종이 오늘 할인 중이에요.`
- `남은 빵 7개`
- `관심빵에 담기`
- `오늘 가격으로 구매하기`

피하기:

- `스코어 산출 결과에 따라 할인 티어가 적용되었습니다.`
- `포트폴리오 히트율을 확인하세요.`
- `사용자 맞춤형 인터랙션을 시작합니다.`

## 8. 접근성 체크리스트

- [ ] 키보드만으로 탭, 상품, 바텀시트, 수량 조절 가능
- [ ] 포커스 표시가 배경과 명확히 구분됨
- [ ] 상승/하락을 색만으로 전달하지 않고 화살표와 수치를 함께 표시
- [ ] 관심 버튼에 현재 상태를 읽을 수 있는 레이블 제공
- [ ] 바텀시트가 열리면 포커스가 내부로 이동하고 닫을 때 원래 위치로 복귀
- [ ] 이미지 대체 텍스트에 상품명 포함
- [ ] 200% 확대 시 가로 스크롤 없이 주요 기능 사용 가능
- [ ] 모션 감소 설정에서 자동 이동과 반복 애니메이션 중지

## 9. 구현 우선순위

### 1차 — 반드시 적용

1. 히어로 정보 위계 재정렬
2. TODAY 상품 그리드 단순화
3. 데스크톱 TODAY/MY 2열 구조
4. 컬러와 타이포 시스템 통일
5. 모바일 터치 영역 및 글자 크기 개선

### 2차 — 품질 개선

1. 바텀시트 정보 구조 정리
2. 빈 상태 문구와 행동 개선
3. 모션 수와 재생 조건 정리
4. 접근성 검증

### 이번 리뉴얼에서 제외

- 새로운 기능 추가
- API 또는 가격 산정 로직 변경
- 신규 이미지 생성
- 별도의 디자인 시스템 패키지 도입
- 사용하지 않는 미래 기능용 컴포넌트 제작

## 10. 완료 기준

다음 질문에 모두 `예`라고 답할 수 있어야 한다.

1. 첫 방문자가 3초 안에 `주식시장과 빵 할인이 연결된 서비스`임을 이해하는가?
2. 오늘 할인율과 구매 가능한 빵을 스크롤 한 번 안에 찾을 수 있는가?
3. 전통적인 막지 브랜드와 현대적인 실시간 서비스가 동시에 느껴지는가?
4. 모바일에서 가격, 남은 수량, CTA가 작거나 복잡하지 않은가?
5. 장식이나 애니메이션을 제거해도 정보 구조가 명확한가?
6. 기존 데이터 로직과 구매 흐름을 변경하지 않았는가?
