# 계좌 데이터를 어떻게 받을 것인가

## 왜 이 문서가 필요한가

2차 멘토링에서 멘토가 우리 안의 연결 논리를 이렇게 잘랐습니다.

> **"변동폭이 빵값에 주는 이 연결부터가 저는 애매한 것 같아요. 억지로 이어 붙인 것 같아요.
> 억지로 이어 붙이면은 사실 스스로도 지금 설득이 안 되지 않아요?"**

그리고 소비자 행동으로도 이어지지 않는다고 했습니다.

> *"오늘 제가 낮에 주식을 했어요. '어, 등락폭이 컸네?' '아, 빵 먹으러 가야지?'"* — 그렇게 안 된다

**해법은 연결의 주어를 바꾸는 것입니다.**

```
지금   시장 전체가 움직였다  →  빵값이 바뀐다      ← 나와 무관. 억지
바꿈   내가 오늘 벌었다      →  내 빵값이 바뀐다    ← 나와 직결
```

코스피 1.8%는 남의 일이지만 내 계좌 +12만원은 내 일입니다.
**"등락폭 컸네 → 빵 먹으러"** 는 안 되지만 **"오늘 벌었네 → 뭐라도 사자"** 는 실제로 있는 행동입니다.

그런데 이 방향의 **유일한 약점이 "내 손익을 어떻게 아느냐"** 입니다. 이 문서가 그 답입니다.

---

## 1. 막혀 있는 길 — 먼저 지웁니다

| 경로 | 왜 안 되나 | 확인 |
| --- | --- | --- |
| **증권사 오픈API** (한국투자증권 등) | 앱키가 **본인 명의 계좌**로만 발급됩니다. 가족 명의도 안 됩니다. 손님이 자기 앱키를 우리에게 주는 것은 **주문 권한까지 넘기는 행위**입니다 | KIS Developers 공식 |
| **금융 마이데이터** | 본인신용정보관리업은 **금융위 허가업**입니다. 자본금 5억 + 물적설비·대주주 적격성 등 6개 요건 | 신용정보협회 / 금융위 |
| **증권사 직접 제휴** | 기업 규모·기간상 단기간에 불가 | 판단 |

### ⛔ 절대 하지 않을 것

**아이디·비밀번호·앱키를 어떤 형태로도 받지 않습니다.**

발표에서 "계좌 연동은 어떻게 하나요?" 질문이 나와도 답은 **"그 방식은 하지 않습니다"** 입니다.
이건 기술 선택이 아니라 원칙입니다 — 받는 순간 우리가 남의 주문 권한을 보관하게 됩니다.

## 2. 우회로 A — 스크린샷 업로드 ★ MVP 추천

MTS 앱의 **수익률 화면을 캡처해서 올립니다.** 이미지를 LLM이 읽습니다.

```
장 마감 → MTS 열어 오늘 수익 확인   (어차피 하는 행동)
       → 스크린샷                  (2초)
       → 빵장에 업로드
       → 도사가 읽고 오늘 내 빵값 결정
```

### 왜 거래내역 CSV보다 나은가

| | 거래내역 CSV 다운로드 | **스크린샷** |
| --- | --- | --- |
| 어디서 | **PC에서 HTS 접속** → 조회 → 저장 | 폰에서 바로 |
| 걸리는 시간 | 2~3분 | **2초** |
| 증권사별 포맷 | 제각각이라 파싱 필요 | 이미지라 무관 |
| 이미 하는 행동인가 | 아니오 | **예** — 장 끝나고 수익률 화면은 어차피 봅니다 |

멘토가 1차에서 말한 것을 **더 낮은 허들로** 구현하는 것입니다.

> *"HTML로 임포트(파일 업로드) 기능만 먼저 만들고 'API로 연결하면 실시간으로 됩니다'라고 설명하면 된다"*

### 개인정보를 설계에 박아둡니다

이건 방어가 아니라 **신뢰 포인트**입니다. 발표에서 먼저 말하면 질문이 줄어듭니다.

```
· 업로드 화면에 안내 — "계좌번호·이름이 보이면 가려주세요"
· 이미지는 읽고 즉시 버립니다. 서버에 저장하지 않습니다
· DB에 남는 것은 숫자 하나 — 오늘 손익률
```

### 조작은 구조로 막습니다

이미지는 편집할 수 있습니다. 그래서 **편집해서 얻을 이득 자체를 작게** 만듭니다.

- 할인 상한 **38%** (기업 확인값)
- **1일 1회**
- 손익률 **±5% 이상은 같은 구간** — 아무리 부풀려도 더 안 내려감

편집 노력 대비 이득이 **빵 한 봉지에 몇백 원**입니다. 멘토가 말한 영역입니다.

> *"포춘쿠키는 대박 날 거라고 했는데 대박 안 나도 따지지 않잖아요. 대신에 우리만의 논리·근거, 그것만 주면 돼요."*

## 3. 우회로 B — 계좌를 아예 안 받습니다 ★ 병행 추천

**관심 종목을 하나 고릅니다.** 그 종목의 오늘 등락이 내 빵값을 정합니다.

```
"오늘 내 종목: 삼성전자"
        ↓
삼성전자 오늘 −2.3%
        ↓
"고생하셨습니다. 위로가로 드릴게요"  →  −15%
```

| 장점 | 내용 |
| --- | --- |
| **허들 0** | 클릭 몇 번. 업로드도 개인정보도 없음 |
| **조작 불가** | 종목 등락은 공개 데이터 |
| **주식 안 하는 사람도 참여** | "삼성전자 하나 골라두기"는 누구나 할 수 있음 |
| **데이터 확보 쉬움** | 종목 시세는 공개 API로 수집 — 지금 코스피 받아오는 경로 그대로 |
| **RFP 충족** | 개별 종목도 금융시장 데이터입니다 |

**약점**: 실제 내 손익이 아니라 "만약 내가 이걸 샀다면"의 가상입니다. 도사 콘텐츠가 얕아집니다.

---

## 4. 결론 — 둘 다 엽니다

```
주식 하는 사람      →  스크린샷 업로드   →  실제 손익   →  도사가 깊게 읽음
주식 안 하는 사람    →  관심 종목 고르기  →  종목 등락   →  가볍게 참여
```

이 구성의 값어치는 세 가지입니다.

1. **허들 문제가 사라집니다.** 업로드가 **선택**이 됩니다 — 하기 싫으면 종목만 고르면 됩니다
2. **멘토의 ④번 지적이 뒤집힙니다.** 방문 동기가 "코스피 보러"가 아니라
   **"내 종목 어떻게 됐나 / 오늘 내 정산 보러"** 가 됩니다
3. **타깃이 넓어집니다.** 주식 관심자로 좁혔던 타깃에 일반 고객이 다시 들어옵니다

## 5. 로드맵

| | 방식 | 시점 |
| --- | --- | --- |
| **Phase 1** | 스크린샷 업로드 + 관심 종목 선택 | **지금 만들 수 있음** |
| **Phase 2** | 마이데이터 **중계업체 제휴** (허가 불필요한 제휴 형태) | 기업이 계약 |
| **Phase 3** | 증권사 직접 제휴 / 오픈API 연동 | 기업 규모 커진 뒤 |

발표에서는 **"지금은 캡처 한 장, 나중엔 자동 연동"** 으로 설명합니다.
멘토가 *"페이크로 놔도 된다"* 고 한 자리가 정확히 여기입니다.

## 6. 지금까지 만든 것이 얼마나 쓰이나

입력만 바뀌고 **구조는 그대로**입니다.

```
지금   |코스피 등락률|   →  구간  →  할인 폭  →  카페24 상품가 변경
바뀜   |내 손익률|       →  구간  →  할인 폭  →  카페24 쿠폰 발급
       |내 종목 등락률|
```

| 자산 | 재사용 |
| --- | --- |
| 구간 테이블 · 관리자 설정 화면 | **그대로** — 읽는 값만 바뀜 |
| 상한 38% 코드 강제 | 그대로 |
| 카페24 OAuth · 토큰 자동 갱신 | 그대로 |
| 카페24 연동 | **쿠폰 발급**으로 전환. 앱 권한에 프로모션 읽기/쓰기를 **이미 넣어뒀습니다** |
| 코스피 수집 경로 | 개별 종목 시세 수집에 그대로 사용 |
| 호가창 화면 | 보완안으로 유지하거나 손익 구간 시각화로 재활용 |

**버리는 것은 "코스피 전체 등락 → 전체 할인"이라는 연결 한 줄**뿐입니다.

## 7. 이번 주 할 일 (멘토 지시)

멘토가 *"원래 거 보완 1개 + 새 거 1개 만들어 와라"* 라고 했고,
*"정리되면 보내달라, 제 관점에서 피드백 드리겠다"* 고 먼저 제안했습니다.

**① 기업에 RFP 불변 여부 확인** ← 답이 오래 걸리니 가장 먼저

```
9월 9일 버전 추가 요구사항 관련 확인드립니다.

1) "금융시장 데이터를 가격 변경 기준으로 활용" — 확정된 요구사항인가요,
   대안을 제안드려도 되는 범위인가요?
2) 여기서 '금융시장 데이터'에 고객 개인의 거래 내역·손익이 포함되나요?
   시장 전체 지수가 아니라 개인 투자 결과에 따라 가격을 다르게 하는 방식을 검토 중입니다.
3) 개인별로 다른 가격을 적용하려면 쿠폰 발급이 필요합니다. 가능한가요?
```

**② 두 안 작성**
- 보완안: 빵장 호가창 — 재고 통제 논리와 기대효과 숫자를 채워서
- 새 안: 개인 손익·종목 연동 (이 문서 내용)

**③ 아이디어 한 문장** — 멘토: *"한 문장 말씀해주셔서 이게 다 이해가 됐거든요"*

> **주식으로 오늘 얼마를 벌었든 잃었든, 그 하루를 빵 한 봉지로 정산해 드립니다.**
