# 막지 빵장 (MAKJI Bread Market)

㈜스윗앤스위츠 웰니스 베이커리 **MAKJI(막지)** 기업연계 프로젝트.
코스피가 오늘의 빵값을 정하는 자사몰 커머스 — Food FinCommerce MVP.

> **국장이 끝나면, 빵장이 시작된다.**
> 오르면 든든한 한 끼, 내리면 달달한 위로. 株式 & 主食.

**왜 만드나** — 자사몰 월 로그인 90회, 월 주문 147건. 주문은 나오는데 **다시 올 이유**가 없다.
**어떻게 파나** — 매일 바뀌는 숫자(코스피)가 그날의 할인을 정한다. 어제와 오늘의 가격이 다르면 확인하러 온다.
**누가 쓰나** — 막지 자사몰 방문자. 로그인도 개인정보도 없이 브라우저 표식만으로 동작한다.

## 하루의 구조

| 시각 | 무엇이 | 상태 |
|---|---|---|
| 09:00 – 15:30 | 코스피 실시간. "지금 마감한다면" 예상 폭 | 국장 LIVE · **상품은 정가** |
| **15:30** | 종가로 오늘의 폭 확정, 빵장 개장 | 대상·가격 공개 |
| 15:30 – 24:00 | 오늘 가격으로 구매, 관심빵 담기 | **빵장 OPEN** (8시간 30분) |
| 24:00 | 할인 종료, 자사몰 가격 복원 | 빵장 마감 |
| 주말 · 공휴일 | 가격은 정가. 주간 활동 결산과 배당 | **휴장** |

주식시장이 쉬는 날은 빵장도 쉰다. "시장이 열리는 날만 가격이 움직인다"가 규칙이다.

## 주요 기능

- **오늘의 빵시장** — 코스피 등락폭이 할인율을, 방향이 대상 라인을 정한다. 상승 = 식사형, 하락 = 달달한 위로.
- **내 관심빵 포트폴리오** — 담아둔 빵을 비중으로 보여준다. 내 1순위가 오늘 할인이면 알려준다.
- **절기빵 공모** — 다음에 나올 빵을 청약으로 고른다. 오늘 산 사람에게 청약권이 생긴다(구매 = 증거금).
- **주말 배당** — 평일 활동을 주간 점수로 결산해 휴장일에 돌려준다. 관심빵 담기 · 구매 · 거래일 출석, 각각 주 1회.
- **관리자 콘솔** — 할인 구간·공모 회차·배당 예산을 배포 없이 바꾼다. 자사몰 반영은 사람이 승인한다.

## 가격 산식 (v5)

```
오늘 이 빵의 할인율
  = MIN( 구간 기본 + 하락장 + 수요 보정 + 재고 보정,  38%,  상품별 상한 )

    구간 기본   최대 30%   코스피 일간 절대 등락폭
    하락장      +3%p       내려서 마감한 날
    수요 보정   +3%p까지   관심은 높은데 구매전환이 낮은 빵
    재고 보정   +2%p까지   판매속도 대비 재고가 많이 남은 빵
    ────────────────────
    합계 최대   38%        규칙 자체의 최대가 상한과 같다 — 절삭이 필요 없다
```

구간 경계는 코스피 **5년 1,218거래일 실측 분포**로 잡았다.

| 등락폭 | 기본 할인 | 실측 빈도 | 연 환산 |
|---|---:|---:|---:|
| 0 ~ 0.3% | 5% | 22.2% | 54일 |
| 0.3 ~ 0.8% | 10% | 28.1% | 69일 |
| 0.8 ~ 1.5% | 15% | 26.4% | 65일 |
| 1.5 ~ 2.5% | 20% | 14.1% | 35일 |
| 2.5% 이상 | 30% | 9.2% | 23일 |

기본 할인 기대값 **13.5%**. 앞 세 구간이 고르게 나와 "매일 폭이 다르다"가 성립한다.

> 코스피는 **원가 지표가 아니라 응원 지표**다. 빵 원재료 가격과의 경제적 인과를 주장하지 않는다.

## 시작하기

```bash
cd web
npm install
cp .env.local.example .env.local   # 없으면 아래 표대로 직접 만든다
npm run dev                        # http://localhost:3000
```

| 환경변수 | 쓰는 곳 | 없으면 |
|---|---|---|
| `SUPABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY` | 예약·관심·출석·공모 저장 | 서버 메모리로 동작(재시작 시 소실) |
| `ADMIN_PASSWORD` | `/admin` 로그인 | 관리자 화면 진입 불가 |
| `CAFE24_MALL_ID` · `CAFE24_CLIENT_ID` · `CAFE24_CLIENT_SECRET` · `CAFE24_API_VERSION` | 자사몰 재고·가격 연동 | `products.ts`의 값으로 폴백 |
| `PRICE_SYNC` | 자사몰 판매가 실제 반영 | **꺼짐**(계산만, dryRun) |
| `CRON_SECRET` | 크론 인증 | 크론 라우트 거부 |
| `SITE_ORIGIN` | 카페24 OAuth 콜백 | Vercel 도메인 추정 |

> `PRICE_SYNC`는 켜는 순간 **실제 makji.kr 판매가가 바뀐다.** 기업 승인 전까지 끈 상태로 둔다.
> 그래서 관리자 화면이 아니라 환경변수에 있다.

**DB는 `web/supabase/지금_실행할_SQL.sql` 한 장을 Supabase SQL Editor에 붙여넣으면 된다.**
맨 아래 확인 쿼리가 빠진 표·열을 위로 올려준다.

## 자동화

| 크론 | 스케줄 (UTC) | KST | 하는 일 |
|---|---|---|---|
| `/api/cron/publish` | `30 6 * * 1-5` | 평일 15:30 | 오늘의 폭을 자사몰 판매가에 반영 |
| `/api/cron/restore` | `10 15 * * 1-5` | 평일 00:10 | `daily_plans`의 원가로 되돌림 |

복원은 **기록해 둔 원가만** 쓴다. 기록이 없으면 아무것도 하지 않는다 — 추측으로 가격을 쓰지 않는다.

## 주의

- **API 키는 커밋하지 않는다.** `.env.local`로 관리하고 `.gitignore`에 들어 있다.
- **상품 콘텐츠 AI 자동 생성·업로드 금지.** 이미지·상품 콘텐츠는 브랜드 자산이라 기업 승인을 거친다.
- 카페24 연동 테스트는 실제 자사몰이 아니라 **팀별 무료체험몰**에서 한다.
- 방문자 구분은 서버 발급 난수다. 누구인지는 모르고 **같은 브라우저인지만** 안다 — 쿠키를 지우면 다시 센다.
